01 / EVIDENCE LEVELS

Three distinct claims

↑ Index

Historical auditability

The public record documents decisions, evidence, retained experiments and known limits.

Functional reconstruction

A new build is produced from documented inputs and validated on the target. This remains an open validation gate.

Bit-for-bit reproducibility

The specified source, toolchain and environment reproduce identical bytes. This is not currently claimed.

05 / OPEN GATES

Requirements for stronger reconstruction claims

↑ Index

A supported functional reconstruction requires a clean build from explicit dependency/toolchain pins, a defined accepted patch sequence, successful AArch64 build checks and target visual/input/audio/exit validation.

A bit-for-bit claim additionally requires exact source identity, dependencies, compiler/linker versions, flags, deterministic metadata and matching post-processing steps.

Until those requirements are demonstrated, the public documentation retains the narrower evidence level.

06 / LICENCE

Redistribution boundary

↑ Index

The retained private V1 incorporated VirtuaAPU. At the audited revision, that component did not contain an explicit published licence file.

The public project therefore does not redistribute VirtuaAPU or the V1 executable incorporating it. Source-side integration documentation remains available independently of that binary-distribution boundary.
