01 / RESTORATION

Preserve the work, remove justified technical obstacles

↑ Index

The project treats the finished game as the primary creative authority. Native execution is used to restore and present that work, not to redesign it.

Painting-restoration model

A conservator does not repaint or add detail, but familiar degradation is not automatically part of the original work. The same distinction is applied to technical defects in software.

Correct demonstrated defects

Known bugs, crashes, save problems, avoidable slowdowns or stutter can be corrected when the creative work remains intact. If defect versus design is uncertain, preservation is the default.

Curated reference

The project selects and validates one coherent preservation configuration instead of requiring the player to build it from many micro-settings.

Original presentation

The reference image is 240x160 at exact 3x integer scale to 720x480, without smoothing, shaders or instructional overlays over the game image.

Menus without visual intrusion

Project Picori menus remain accessible through shortcuts, while its instructional overlays are disabled by default so they do not cover the original presentation.

Preserve control identity

Original GBA controls remain reserved for gameplay. Device-specific port functions use combinations that do not replace those controls.

Efficiency after fidelity

Once fidelity and stability are satisfied, unused performance is treated as reserve. Reduced clocks are preferred when they retain the validated experience instead of consuming resources without purpose.

Document restored differences

When a technical restoration changes observable historical behaviour, the difference and supporting evidence are recorded transparently.

02 / TIMING

Separate game cadence from display refresh

↑ Index

The accepted direction keeps game logic around 59.7275 Hz, uses the panel around 119.455 Hz, and performs one explicit presentation per logical tick.

In the recorded comparison, tick-lateness p95 improved from approximately 5.791 ms to 0.028 ms under the tested conditions.

The result concerns presentation timing and is not presented as 120 FPS game logic.

03 / AUDIO

Combine instrumentation with listening

↑ Index

Audio work on Cortex-A53/H700 combined callback/timing evidence with human listening. Later retained configuration evidence uses audio 1600, with a nominal interval around 33.333 ms.

A callback-gap/outlier warning remained in the record. It is treated as instrumentation evidence rather than a direct count of audible defects.

04 / BENCHMARKING

Use a representative launch context

↑ Index

Early AutoLab measurements obtained through direct SSH were rejected because the surrounding frontend/background state did not represent a normal Ports launch.

Later comparisons used a normal Ports-session context, deterministic replay and CPU/GPU restoration between variants.

The retained V1 uses CPU ceiling 936 MHz and GPU 420 MHz. The lower clocks were selected with the objective of avoiding unnecessary power and thermal demand after fidelity and stability requirements were met; clock reduction is not converted into an unmeasured battery, power or temperature percentage.

05 / EXPERIMENTS

Retain useful negative results

↑ Index

GPU renderer

An experimental GPU renderer failed and was not promoted.

Fullscreen clear

A fullscreen-clear experiment was evaluated but not adopted into the retained V1 line.

Mixed optimisation data

The record also retains less favourable observations, including higher maximum temperature in one comparison and slightly higher RSS.

These are technical investigations used to define engineering boundaries, not an alternative creative direction for the game.

06 / RELEASE PROCESS

Keep validation and publication as separate gates

↑ Index

Local validation, repository publication, deployment and live verification are tracked separately.

Release preparation also distinguishes redistribution restrictions from documentation scope so that safe engineering information can remain public even when a binary or dependency cannot be distributed.
