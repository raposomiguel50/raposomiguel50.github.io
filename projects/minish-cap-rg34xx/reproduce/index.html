02 / INPUTS

What inputs are available?

↑ Index

The repository contains 15 historical patches, a launcher, source identifiers and selected test records.

The foundation is EstebanPdN's Project Picori-derived source. The exact revision is recorded in the source baseline.

Four retained source snapshots do not form a complete final build environment. The full upstream tree is not included here.

03 / REFERENCE BUILD

Which build is the reference?

↑ Index

The acceptance record identifies an 8,858,736-byte private executable. It records one manual session with visual/audio OK, plus two preceding automated soaks.

Recorded settings include CPU/GPU ceilings of 936/420 MHz, an audio request of 1600 frames and three rendering threads.

These identify a tested private configuration. They do not establish a full playthrough or a successful public rebuild.

View its fingerprint and source records

04 / STARTING POINT

Where should reconstruction start?

↑ Index

Use a separate worktree. Leave private V1, saves and earlier evidence untouched.

Inspect the pinned upstream and each patch's purpose. Some patches overlap; some only add diagnostics.

Do not apply every patch in filename order. Select compatible changes, then build and test each stage.

Read the patch map before changing source

05 / REQUIREMENTS

What is still needed?

↑ Index
  1. A complete source, dependency and toolchain list.
  2. A compatible patch order and exact build settings.
  3. Generated inputs, final processing steps and build logs.
  4. The new executable's fingerprint and fresh device tests.

Recalculating statistics is a different task. The analysis script is public, but the full raw traces remain in the private archive.
