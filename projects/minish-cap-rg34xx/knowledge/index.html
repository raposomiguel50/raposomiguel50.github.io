01 / SCOPE

What was implemented

↑ Index

The audited source has 15 patches: build/link and header-order changes, Cortex-A53 targeting, handheld menu/input integration, shutdown handling, an audio-resampling policy and presentation instrumentation/policy changes. The full inventory identifies each file and its role (see patches and launcher).

The 29 August P10.3.2 verdict records one settings-open/close pair, one MENU+L2 exit marker and operator-signalled legacy-hint checks. This supports specific integration checks, not correction of original GBA gameplay bugs (see runtime records).

The restoration philosophy is the approved decision framework. It is not an empirical list of fixes already performed.

02 / TIMING

Two captures, with outliers retained

↑ Index

P11.3 contains 10,203 ticks and P11.4 contains 10,449. Recalculated lateness p95 is 5.790787 ms versus 0.027887 ms. The median presentation-call interval is 7.469125 ms versus 0.569417 ms; its maximum is 46.450584 ms versus 60.917250 ms. A better median coexists with a worse maximum (see runtime records, REANALYSIS.json).

P11.4 targets a render period equal to one logic tick. The trace has 63 zero-presentation, 10,346 one-presentation and 40 two-presentation ticks. Both captures retain a 16.742706 ms logic period. The reported display mode around 119.455 Hz is not 120 FPS game logic.

These are within-session observations, not thousands of independent test runs. The audit does not establish randomized order, identical workloads or full-game coverage for the pair. The intervals are not end-to-end input-latency measurements.

03 / AUDIO

Source policy, request and listening

↑ Index

The A53 patch selects LINEAR for one enhanced-resampling branch, while the gbaAccurate branch still selects NEAREST. This is a conditional code change, not proof of one resampler in all modes (see patches and launcher).

The P11.4 comparison records an audio setting of 1920 frames. The later launcher requests 1600, but retains a printed diagnostic of 1920. The negotiated buffer size is not established from those strings. Final operator audio acceptance is OK, not a signal-equivalence or universal defect-free result (see runtime records).

04 / BENCHMARKING

Keep stage and sample boundaries visible

↑ Index

The P12 R2.6 workflow note reports invalidation of direct-SSH results and a normal muOS Ports-session procedure with deterministic replay. It reports one menu launch and zero manual gameplay sessions during its six automated streams. This later procedure must not be assigned retrospectively to the earlier P11 pair (see workflow notes).

The final P13.1 acceptance separately records one manual session, two preceding automated soaks and 874 monitor samples. Maximum reported temperature is 52.6 °C. All monitor rows report CPU maximum 936 MHz and GPU maximum 420 MHz. Stage-A energy values are null; no energy-saving percentage is established (see runtime records, REANALYSIS.json).

05 / OPEN FINDINGS

Retain contradictions and rejected work

↑ Index

Selection, not universal improvement

The stored P13.1 comparison has a +5.3 °C maximum-temperature delta and an RSS median ratio of 1.003497. The workflow note records rejection of the GPU-renderer path; the chosen backend is SDL_RENDERER and the clear-skip experiment is not adopted.

Conflicting runtime messages

The log describes save states as inert but records quicksave/autosave ring writes. Two out-of-ROM pointer warnings also remain. Their causes and gameplay impact are not established by this audit.

Restoration scope

The recorded display mode and CPU/GPU limits match before/after. The CPU governor changes from powersave to ondemand. Thus the session does not prove restoration of the entire prior system state.

Sources: runtime records, REANALYSIS.json and workflow notes. These are documentary findings, not newly diagnosed runtime bugs or authorization to modify the private V1.
