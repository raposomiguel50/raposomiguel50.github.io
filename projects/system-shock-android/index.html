System Shock — Android

A native Android/ARM64 adaptation of Shockolate, developed around the Retroid Pocket 5 as the primary reference device. The goal is to preserve the structure and feel of the 1994 game while making its desktop-era presentation, input and audio systems work naturally on a modern Android handheld.

ACTIVE DEVELOPMENT Canonical internal baseline: P2.0B + P2.0A Hor+ Updated 19 August 2026
Shockolate upstream Baseline commit References

01 / OVERVIEW

What this port is

Source-port foundation

The port uses Shockolate as its code foundation. Shockolate is a cross-platform System Shock source port built around SDL2 and itself traces back to source released by Nightdive Studios. The Android work is based on upstream commit 4cc3d07dfff2d11b6d3a0a9960a51cf4ca253690.

Hardware-led development

The Retroid Pocket 5 is treated as a real target rather than a generic Android endpoint. Display behavior, controller routing, Android lifecycle, audio timing, text input and widescreen presentation are validated against the handheld itself.

Commercial data stays external

No proprietary System Shock game data is stored in the public source tree or distributable packages. Development uses legally obtained game data kept outside the redistributable source tree. Anyone reproducing the port must supply their own compatible game data separately.

02 / CURRENT STATE

Implemented and validated

PLATFORM Android / ARM64

Native C/C++ game code packaged through the Android toolchain rather than desktop emulation.

DISPLAY 4:3 + Hor+

Original 1024×768 logical presentation retained as a no-stretch baseline, with a validated 1366×768 Hor+ mode and centered 1024×768 UI safe area.

INPUT Handheld-first controls

Right-stick camera look is the default. A View/Select toggle switches the right stick into fine cursor mode for the original interface.

AUDIO SDL_mixer + ADLMIDI

A single mixer device handles game audio, while the music scheduler has been adjusted to avoid catch-up bursts after host stalls.

TEXT ENTRY Android IME

The Android on-screen keyboard is integrated for player names and other text-entry paths that were designed around a desktop keyboard.

STATUS Beta / active R&D

The core port is playable; graphics and font remaster work remains research-driven and is not treated as complete until it passes fidelity gates.

03 / CONTROLS

Desktop interaction translated to a handheld

System Shock combines free-look movement with a mouse-driven interface. The port therefore keeps both interaction models available instead of forcing one control scheme to do everything.

Input Default behavior
Left stick Player movement.
Right stick Camera rotation / look by default.
View / Select Toggles the right stick between camera-look and fine cursor/mouse mode.
L2 Left-mouse style selection, interaction and drag behavior for the original UI.
R2 Right-mouse path used by the original control model.
Touchscreen Optional pointer-style interaction; it can be used as a mouse rather than being mandatory.
Android keyboard Text entry for player names and other keyboard-oriented fields.

SDL's Android layer supports touch input and synthetic mouse behavior, which provides a useful bridge for software whose original interface assumes a mouse. See the SDL Android documentation in the references below.

04 / PRESENTATION

Preserve first, extend second

4:3 baseline

The original game rendering remains logically 1024×768. On Android, the physical display surface is kept platform-owned while the game is presented without non-uniform stretching.

Hor+ widescreen

A 1366×768 logical mode expands the world horizontally while retaining a centered 1024×768 safe area for the original UI. The 4:3 mode remains available as a reversible fallback.

HD research

Private extraction tooling has catalogued 8,870 supported image frames. Indexed sprite/UI scaling can remain exact, but world/static imagery requires more careful reconstruction than a simple upscale or late overlay.

Font reconstruction

The current research focus is an offline remaster of the original font resources. The validated dataset contains 36 fonts and 5,696 glyphs; contour/vector candidates are being evaluated before any runtime integration.

Several experimental HD/font approaches have deliberately been rejected. They remain research history, not the shipping baseline. A visual change is not promoted simply because it is sharper; it must preserve layout, readability and original asset identity.

05 / TECHNICAL STACK

Build and runtime foundation

Game/source-port base Shockolate 0.7.8 lineage, upstream baseline commit 4cc3d07….
Primary languages C/C++ game code with Java/JNI Android integration.
SDL SDL 2.32.10, release commit 5d249570….
Audio SDL_mixer 2.8.1 plus Shockolate's ADLMIDI/OPL3 path.
Android build Android SDK/NDK, Gradle 8.1.1, CMake/ndk-build integration and JDK 17.
Reference hardware Retroid Pocket 5 — Android 13, Adreno 650, 8 GB RAM, 5.5-inch 1080p/60 Hz AMOLED according to Retroid's product specification.

06 / RELEASE & LICENSING

Open code, separate game data

Port status

No public APK is published from this page yet. Development is still active and current work is focused on presentation fidelity rather than declaring a final release prematurely.

Source licensing

Shockolate is distributed under the GNU GPL v3.0. Any public distribution of this derivative work will preserve the applicable upstream and third-party license obligations.

Game ownership

The project does not provide System Shock's proprietary resources. A legally obtained copy of compatible game data is required separately. The development copy used for testing is external to the source tree and handover packages.
