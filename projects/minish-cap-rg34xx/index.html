The Minish Cap - RG34XX

An unofficial RG34XX/H700 integration of Project Picori, built around preservation, containment, focus, restoration and minimal intervention.

The goal is not only to provide a port. It is to preserve the reasoning, failures and evidence so other developers can reuse the method.

01 / OVERVIEW

A port used to learn the platform

↑ Index

Project Picori foundation

The integration is based on Project Picori revision e72663ca4059dabf9dbf7f03c36fc791d90b8db5. The public repository publishes the H700 integration layer rather than duplicating the complete upstream tree.

Hardware-led reference

The ANBERNIC RG34XX-H, Allwinner H700 and muOS form the validated reference configuration. Host builds remain development aids; target behaviour is a separate authority.

Teaching output

The public result includes patches, launcher material, provenance, failures, measurements, claim limits and reconstruction status. The reasoning is part of the deliverable.

02 / PHILOSOPHY

Small interventions, solid foundations

↑ Index

This project deliberately resists the idea that newer, larger or more visible is automatically better. Improvements have to earn their place against the preservation goal and the target evidence.

Preservation

The original game remains authoritative for art, music, SFX, interface, cadence and control identity.

Containment

Solve the demonstrated build, timing, audio or lifecycle problem without turning each issue into a whole-engine redesign.

Focus

Research can remain research. Optional remastering or experimental renderers do not become required scope merely because they are technically interesting.

Restoration

Prefer adapting the original behaviour to the new environment instead of replacing the experience with a new interpretation.

Minimalism

Use the smallest justified technical intervention. Minimalism does not mean minimal documentation: the evidence and reasoning should remain visible.

Independent judgment

Trends, hype, marketing language, consumer pressure and feature-count escalation do not set project priorities. Need and evidence do.

04 / VALIDATION

Evidence without inflated claims

↑ Index

Retained private V1 SHA-256:

787ba3cb8c297ea44a0605745347fe5a6e792094f0be755b51a8200c1eadc710

Timing

Accepted direction: logic ~59.7275 Hz, panel ~119.455 Hz, one explicit presentation per logical tick. A recorded comparison improved tick-lateness p95 from ~5.791 ms to ~0.028 ms.

Runtime evidence

Later retained configuration evidence includes CPU936, GPU420, audio1600 and TMC_RENDER_THREADS=3.

Claim discipline

These numbers are not converted into unsupported claims such as 120 FPS gameplay, 33.9% battery savings, universal H700 compatibility or bit-for-bit reproducibility.

05 / PUBLICATION

Safe boundary, open knowledge

↑ Index

Published

Source patches, launcher/runtime integration material, reference hashes, philosophy, knowledge base, patch map, validation, reconstruction status and development method.

Not published

No GBA ROM, extracted Nintendo assets, saves, private builds, device backups or validated V1 executable are included.

VirtuaAPU boundary

The private V1 used VirtuaAPU. The audited revision had no explicit published licence file, so its source and the executable incorporating it are not redistributed.

The first publication was too narrow editorially. The correction is now explicit: sanitise restricted material; do not sanitise away safe engineering knowledge.

06 / PORTMASTER

Not submission-ready yet

↑ Index

A future PortMaster package remains a separate distribution milestone. It is currently blocked by two genuine requirements:

  • a clean redistribution/licensing path for the executable dependency boundary, especially VirtuaAPU;
  • broader CFW/device validation beyond the current RG34XX-H + muOS reference.

Those blockers do not prevent public teaching, documentation or source-side publication.
