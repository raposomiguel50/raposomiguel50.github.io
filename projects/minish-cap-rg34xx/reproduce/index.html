Reconstruction and reproducibility

01 / CLAIMS

Three different levels of evidence

↑ Index

Historical auditability

The public record explains what was tried, why decisions were made, what evidence survived and what was rejected.

Functional reconstruction

A clean new build can be produced from documented inputs and validated on the target. This is a future clean-room reconstruction gate, not yet claimed as complete.

Bit-for-bit reproducibility

The specified source/toolchain/environment recreates identical bytes. This is explicitly not claimed today.

03 / PRIVATE V1

Artifact identity without overclaiming

↑ Index

Retained private V1 SHA-256:

787ba3cb8c297ea44a0605745347fe5a6e792094f0be755b51a8200c1eadc710

The hash identifies the retained executable. It does not prove that the public repository can recreate identical bytes.

Four P13.1 source snapshots were preserved and hash-verified in the private engineering record — port_ppu.cpp, port_gpu_renderer.cpp, port_main.c and xmake.lua — but they are not automatically equivalent to a complete final source/build environment.

05 / MISSING GATES

What still has to be demonstrated

↑ Index

A supported functional reconstruction should be demonstrated from a new clean directory with explicit dependency/toolchain pins, a minimal accepted patch sequence, successful AArch64 build, architecture/link checks, normal Ports-context launch and target visual/input/audio/exit QA.

A bit-for-bit claim would additionally require exact source identity, dependencies, compiler/linker versions, flags, deterministic metadata and identical post-processing steps that reproduce the V1 SHA-256.

Until those gates pass, the public project prefers an honest limitation over a stronger but unsupported label.

06 / LICENCE

Technical validity and redistribution are separate

↑ Index

The retained private V1 incorporated VirtuaAPU. At the audited revision, that component did not contain an explicit published licence file.

Therefore the public project does not redistribute VirtuaAPU or the V1 executable incorporating it. That restriction does not prevent publication of safe source-side integration knowledge.
