01 / REPRODUCIBILITY STATUS

What is public, and what is not

Redistributable source

A sanitized public-source snapshot has been prepared from the validated Android handover. It contains the Android project, the modified Shockolate source snapshot, licenses, provenance, build helpers and open knowledge documentation. It contains no System Shock commercial resource data.

Game data

You must supply your own compatible System Shock resources from a legally obtained copy. The source archive deliberately excludes res/data, res/sound and proprietary .res content.

Evidence boundary

The current code has been validated on the Retroid Pocket 5 during development. The new public package still needs a clean-clone build performed independently of the private workspace before I describe it as independently reproduced.

A separate public source repository is the preferred long-term home. Until that repository is created, the prepared source package is being kept as a release candidate rather than pretending that the website alone is a complete software distribution channel.

1. Bootstrap dependencies

From the public-source root, run pwsh -File .\scripts\bootstrap-deps.ps1. The helper obtains the pinned SDL source and official SDL_mixer 2.8.1 source into the ignored .deps directory.

2. Build

Run pwsh -File .\scripts\build.ps1. If the Android SDK is not in the normal Windows location, pass -AndroidSdk. The expected artifact is AndroidProject\app\build\outputs\apk\debug\app-debug.apk.

3. Verify

Run pwsh -File .\scripts\verify-apk.ps1. The verifier checks the expected ARM64 native libraries and rejects obvious System Shock commercial resource data inside the APK.

03 / GAME DATA

Bring your own compatible resources

Shockolate expects a resource layout containing res/data and res/sound. The port preserves this separation instead of repackaging commercial assets into source or APK releases.

Expected layout

Point the current helper at a local res directory containing both data and sound. The upstream Shockolate documentation states that original CD-ROM or System Shock: Enhanced Edition assets are supported by this source lineage.

Android storage

The native Android entry point changes its working directory to SDL_AndroidGetInternalStoragePath(). The original relative resource paths therefore resolve from the application's private files area.

Current import method

The prepared developer helper uses a debug APK, ADB and Android run-as to copy your own data and sound directories into app-private storage. This is intentionally documented as a developer path, not disguised as a consumer-ready installer.

A graphical game-data importer is an open release-engineering item. A normal signed consumer APK should let a game owner choose/import their own data through Android storage APIs without requiring ADB.

04 / INSTALL & TEST

Debug installation path

Connect a device

Enable USB debugging and make sure adb get-state reports a device. The current helper assumes a single connected target.

Install + data

Run pwsh -File .\scripts\install-debug.ps1 -GameRes 'D:\Path\To\res'. The helper installs the APK, imports your data into the debug application's private storage and launches the activity.

Validate behavior

Check menu/gameplay, 4:3 or Hor+ presentation, right-stick look/cursor toggle, touchscreen pointer behavior, Android text input and game audio. Record device/OS/controller details when reporting compatibility.

05 / FRESH-CLONE GATE

When I will call it independently reproducible

The standard is deliberately stricter than “it builds on my machine.” A clean external path must be able to bootstrap dependencies, build, verify, install, import separately owned game data and reach validated gameplay without relying on my internal workspace or caches.
